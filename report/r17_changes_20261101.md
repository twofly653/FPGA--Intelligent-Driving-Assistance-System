## 2. 改动 A：心跳超时判定（根因修复）

### 2.1 位置

`D:\project\FPGA_PYNQ_Integrated\lcd_english_20261028\src\firmware\src\pc_net_service.c`

### 2.2 改前 / 改后

**改前（错误）：**

```c
if(!netif_is_link_up(&iface)||!heartbeat||t-heartbeat>1500000u){
    if(guard.session){pn_guard_reset(&guard,0,++epoch,flags);obstacle_service_remote_clear();}active=0;return;
}
```

**改后（当前）：**

```c
/* Heartbeat age must be an unsigned-safe subtraction. receive() runs inside
 * gem_poll_input() below and stamps heartbeat with a now_us() sampled after
 * this poll's t, so a plain t-heartbeat wraps to ~2^64 for exactly the poll
 * that carried the HELLO and expires the session every time. t<=heartbeat is
 * a fresh stamp, never an expiry. */
if(!netif_is_link_up(&iface)||!heartbeat||(t>heartbeat&&t-heartbeat>1500000u)){
    if(guard.session){pn_guard_reset(&guard,0,++epoch,flags);obstacle_service_remote_clear();}active=0;return;
}
```

唯一实质差异：`t-heartbeat>1500000u` → `(t>heartbeat && t-heartbeat>1500000u)`。

### 2.3 根因：同一次 poll 内的采样逆序

```c
static void poll(void){
  traffic_frame_snapshot_t f;
  uint64_t t = now_us(), started = t;      /* ① 先采样 t */
  ...
  gem_poll_input(&iface, 8);               /* ② 内部调用 receive() */
  ...
  if(... || t - heartbeat > 1500000u){     /* ③ 用旧的 t 去减新的 heartbeat */
```

```
时间轴 ──────────────────────────────────────────────────►

  t = now_us()          heartbeat = now_us()
      │                        │
      │◄────── 7 µs ──────────►│
      │                        │
   ① 采样                  ② receive() 处理 HELLO 时写入
                              （值比 t 大）

  ③ t - heartbeat = (-7) 按 uint64_t 解释 = 0xFFFFFFFFFFFFFFF9 ≈ 2^64
     → 恒 > 1,500,000 → 判定"心跳超时" → 每秒都触发一次 session 清零
```

因为 `heartbeat` 在 `gem_poll_input()` **内部**被一个更晚的 `now_us()` 刷新，所以**承载 HELLO 的那一次 poll，`t - heartbeat` 必然为负**，而无符号回绕成约 2⁶⁴。

### 2.4 连锁后果（两个症状其实是同一个 bug）

```
HELLO 到达 → 判定"超时" → pn_guard_reset(&guard, 0, ++epoch, flags)
                                  │            │
                                  │            └─► epoch 每秒 +1（疯狂自增）
                                  └─► guard.session = 0

guard.session = 0
   ├─► 出帧 tx.session = 0  → PC 侧 net_protocol.unpack 以 session==0 判非法，整包丢弃
   └─► pn_guard_accept 里 if(h->session != g->session) 恒成立
         → PC 回传的 RESULT 100% 被拒 → obstacle 表 count 恒 0 → 屏上永不出框
```

### 2.5 为什么 `t <= heartbeat` 一定是「刚刷新」，不是「已过期」

`heartbeat` 只在 `receive()` 里被写，且写入值来自**同一时刻或更晚**的 `now_us()`；`t` 是本轮 poll 的起点。
因此 `heartbeat >= t` 只可能意味着"本轮 poll 期间刚收到 HELLO"，物理上不可能是过期。
真正过期时 `heartbeat` 会稳定地落在 `t` 之前一个完整的 1.5 s 以上，此时 `t > heartbeat` 成立，1.5 s 语义完整保留。

## 3. 改动 B：发送中帧存活判定（同型隐患）

同一个 `poll()` 里的第二处 64 位减法存在完全相同的回绕风险，一并修掉：

**改前：**

```c
if(active&&(t-tx_started>150000u||t-tx.capture_us>350000u))active=0;
```

**改后：**

```c
/* capture_us comes from the PL and may sit slightly ahead of t; compare both
 * ages only when the stamp is genuinely older, or the wrap drops the frame
 * mid-transmission. */
if(active&&((t>tx_started&&t-tx_started>150000u)||(t>tx.capture_us&&t-tx.capture_us>350000u)))active=0;
```

**为什么必须改：** `tx.capture_us` 来自 PL 侧的采集时间戳，可能比 APU 的 `t` 略微超前（跨时钟域）。一旦超前，`t - tx.capture_us` 回绕成天文数字，帧会在**传输途中**被判定超时并置 `active=0`，表现为偶发丢帧/半包。

**未改动的相邻代码（本来就写对了，仅作对照）：**

```c
if(t<f.capture_us||t-f.capture_us>200000u)return;   /* 已有 t<f.capture_us 前置守卫 */
```

## 4. 改动 C：PC 侧 `adopt_session()`（兼容层，R16 引入）

`D:\project\FPGA_PYNQ_Integrated\lcd_english_20261028\src\pc_vision\ethernet_tracking.py` L30–L41

```python
def adopt_session(data, session):
    """Rewrite a zero-session datagram to the session this receiver announced.

    The flashed R15 candidate build echoes session 0 in every frame header even
    though it adopts the HELLO session internally, and net_protocol.unpack
    rejects session 0 as malformed. Only the session field and the CRC over the
    first 44 bytes are touched; every other byte and every other validation
    (magic, version, kind, layout, payload CRC) stays exactly as received.
    Datagrams that already carry a session are returned untouched.
    """
    if len(data)<48 or data[:4]!=b'DVN1' or data[8:12]!=b'\x00\x00\x00\x00':return data
```

这是 R16 阶段为了**绕过**板端 session 恒 0 而加的临时兼容层，只改 4 字节 session 并重算前 44 字节 CRC。

**R17 之后它的正当性：** 板端已能回传正确 session，该函数应当**永不命中**。运行时的 `rewrites=0` 就是它未被触发的直接证据，因此保留它作为向后兼容（万一回滚到旧固件仍可用），不删除。

### 8.1 修复前：寄存器级坐实逆序（Exp A）

| `r2` | `0x00000000` | 减出来的"年龄"低字 → 断言成立 |

**`0x2E73BACA < 0x2E73BAD1`，即 `now` 比 `heartbeat` 小 7 µs** —— 采样逆序被直接量化。

### 8.2 修复前：写回值正确（Exp B）

→ 证明 HELLO 分支本身工作正常，问题只在「谁触发了 reset」。

### 8.3 修复前：两个断点双双命中

`0x11c52c`（HELLO 失配）与 `0x11cc90`（超时 reset）**同时被命中**，且每次超时分支都把 `guard.session` 清零
→ 完美解释「epoch 在涨、session 恒 0」这对看似矛盾的观测。

### 8.4 修复后：板上探针实测

## 附录 A：DVN1 私有协议速查（未改动，供对照）

- 帧头 48 字节：`!4sBBHIIIQHHHHIHHI`（`DVN1` 魔数 + ver + kind + flags + session + epoch + frame + capture_us + width + height + index + chunks + total + payload_len + … + CRC32）
- CRC32 覆盖 `header[:44]` + payload
- 分片 `CHUNK = 1344`
- 板端 `pn_unpack` 明确拒绝 `session == 0`
- `receive()` 校验**源端口**必须为 `50011`
- 拓扑：板 `192.168.2.99:50010` ↔ PC `192.168.2.1:50011`，HELLO 心跳 1.5 s 超时门控发帧

## 附录 B：ARM EABI 64 位调用约定（读反汇编时用）

- 64 位返回值用 `r0:r1`
- 64 位实参占 `r2:r3`
- `push {r4,r5,r6,r7,lr}` 不改 `r0–r3`，故 `p = cmp; bl` 模式下 `r0–r3` 在调用入口仍有效（仅 `mov r4,r0` 会覆盖）
