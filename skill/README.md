# 可复用提交检查与 PYNQ 排查工作流

## 适用范围

适用于含 RTL、PS 应用、网页和板测证据的 PYNQ/Zynq 项目。目录检查与项目算法无关；板卡排查需按实际硬件寄存器及供电方式调整。

## 使用方法

从任意目录执行 `python check_submission.py <repository_root>`。脚本只读取文件，检查七类提交目录、文件命名、Markdown 本地文件链接、Python 语法及烧录文件是否存在。`README.md` 为模板特许的大写文件名。缺少 BIT/XSA/ELF 会单独报告，不把源码命名合格等同于可直接烧录。

## 排查提示工作流

1. 明确现象、触发条件和复现步骤，保存日志后再改代码。
2. 分别核查 USB/JTAG、处理器目标、串口所有权、板载传感器应答与 FPGA 接口版本。
3. 下载前核对同一发布包的 BIT、XSA、ELF、PS 初始化脚本；不以文件名或旧启动字符串认定版本一致。
4. 显示/传感器异常而 HDMI 正常时，先按实际电源条件进行冷启动交叉验证，再定位驱动；冷启动只能说明状态恢复，不能证明软件缺陷已修复。
5. 固定输入做优化前后对照，将帧率、算法耗时、端到端延迟分开记录；没有真值时不报告通用准确率。

本项目既有板测见 `../board/r13_20261030/validation.md`、测距交叉验证见 `../board/run_20261029/validation_20261029.md`，网络修复见 `../report/r17_changes_20261101.md`。这些记录促成了版本一致性、串口占用、冷启动和受控输入检查步骤。目录检查脚本的本轮运行结果另存于报告目录。

## 失效条件

静态检查不能证明可综合、时序收敛、传感器精度、动态下载成功或道路安全；不校验外部 URL，也不执行历史下载/实验脚本。缺少硬件、模型、原始输入、BSP 或工具链时，应明确缺项并停止依赖这些条件的验证。不同项目的接口地址、阈值和 GPIO 不能直接照搬。
